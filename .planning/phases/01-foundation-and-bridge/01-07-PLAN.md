  ```typescript
  ngOnDestroy(): void {
    // Critical: Destroy Phaser instance to prevent memory leaks
    if (this.game) {
      // Destroy game instance
      // Parameters: removeCanvas=true, noReturn=false
      // removeCanvas=true removes the canvas from DOM
      // noReturn=false allows proper cleanup callbacks
      this.game.destroy(true, false);

      // Clear reference
      this.game = undefined;
    }

    // Additional cleanup: ensure no orphaned canvas elements
    const container = document.getElementById('game-container');
    if (container) {
      // Remove any remaining canvas elements
      const canvases = container.querySelectorAll('canvas');
      canvases.forEach(canvas => canvas.remove());
    }
  }
  ```

  Add lifecycle logging for debugging (can be removed in production):

  ```markdown
  # Phaser Memory Leak Test Procedure

  ## Objective
  Verify that navigating to /world and away does NOT cause memory leaks or duplicate canvases.

  ## Prerequisites
  - Frontend deployed and running (local or Pi)
  - Chrome or Firefox DevTools available
  - App accessible at http://localhost:4200 or https://thisisvillegas.com

  ## Test Steps

  ### 1. Baseline Memory Measurement

  1. Open browser to /login
  2. Open DevTools → Memory tab
  3. Take heap snapshot → label as "Baseline"
  4. Note memory size

  ### 2. Navigate to /world 5 times

  1. Navigate to /world (wait for Phaser to load)
  2. Navigate back to /login
  3. Wait 5 seconds
  4. Repeat 5 times total

  ### 3. Take Post-Test Snapshot

  1. Stay on /login
  2. Click "Collect garbage" button in Memory tab (trash icon)
  3. Wait 5 seconds
  4. Take heap snapshot → label as "After 5 cycles"
  5. Compare with baseline

  ### 4. DOM Inspection

  1. Navigate to /world
  2. Open DevTools → Elements tab
  3. Count canvas elements (should be 1)
  4. Navigate to /login
  5. Check #game-container (should be empty or not exist)
  6. Navigate to /world again
  7. Count canvas elements (should still be 1, not 2)

  ### 5. Console Check

  1. Open DevTools → Console
  2. Navigate to /world and back 3 times
  3. Look for console logs:
     - "[GameComponent] Initializing Phaser..." on each /world visit
     - "[GameComponent] Destroying Phaser..." on each exit
     - No error messages about WebGL context
     - No warnings about memory

  ## Success Criteria

  ✅ **PASS**: Memory growth < 50MB after 5 cycles + garbage collection
  ✅ **PASS**: Only 1 canvas element exists when on /world
  ✅ **PASS**: No canvas elements when not on /world
  ✅ **PASS**: Console shows proper init/destroy cycle
  ✅ **PASS**: No JavaScript errors in console

  ❌ **FAIL**: Memory grows > 100MB after garbage collection
  ❌ **FAIL**: Multiple canvas elements accumulate
  ❌ **FAIL**: Canvas elements remain after leaving /world
  ❌ **FAIL**: Console shows errors about destroyed scenes
  ❌ **FAIL**: WebGL context errors

  ## Troubleshooting

  If memory leaks detected:
  1. Check ngOnDestroy is being called (add console.log)
  2. Verify game.destroy(true, false) is executed
  3. Check for event listeners not removed
  4. Look for references held by PhaserBridgeService
  5. Check LoadingScene and BootScene for cleanup issues

  If duplicate canvases:
  1. Verify removeCanvas=true in game.destroy()
  2. Check manual canvas cleanup in ngOnDestroy
  3. Look for race conditions in ngAfterViewInit

  ## Automated Testing (Future)

  This test should be automated with:
  - Puppeteer memory measurement
  - DOM snapshot comparison
  - Performance metrics tracking
  ```
